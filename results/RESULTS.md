## 消融分析（E101–E108，回答「为什么不是预期结果」）

三个反直觉结果，全部先查原因再下结论：

1. **BM25 单路几乎不可用（R@5 0.185）**。根因不是 BM25 实现问题，而是**评测集用中文提问、语料是英文文档**：中文 query 分词后与英文正文几乎没有词面重叠，BM25 只能靠代码标识符（`checkpointer`、`rrf` 这类 ASCII 名）命中。所以这条结果说明的是「本项目场景下词法通道失效」，不是「BM25 无用」——若查询语言与语料一致，结论会不同，属已知边界（已写入 README 局限）。
2. **RRF 融合反而比纯向量低 7.6pp（0.370 vs 0.446）**。因为融合是等权投票：BM25 那一路大半是噪音，把向量已经排对的 top-5 挤下去。这是「融合前必须先确认每一路都有效」的教科书反例。
3. **rerank 把结果拉回来并要求更深**：+rerank 后 R@5 0.522、R@1 从 0.174 升到 0.283（翻倍）。cross-encoder 是跨语言的（中文问句对英文片段也能直接打分），所以它能修掉 RRF 的融合噪音——代价是 P95 从 258ms 涨到 1136ms（×4.4），在 8 卡以外的单卡 4060 上仍可接受。
4. **fixed 切分全线崩**（最好也只有 R@5 0.185）：虽然 average chunk 662 字符比 heading 的 383 更长，但断点不看结构，chunk 常常起于半句话、跨两个小节，标题信息全丢。**结论：切分必须跟着文档结构走，不能只调 size。**

→ 当前最优检索配置：**heading 切分 + 混合 RRF + rerank（R@5 0.522, MRR 0.369）**。但注意：E001 baseline 用的是默认配置（rrf 不开 rerank），所以下文 baseline 与消融的检索条件不同，可比性以 RESULTS 表为准。

## E005 分析（240 题，一次跑出两套数字）

明细 `results\eval_E005.jsonl`；拆指标脚本 `src\split_metrics.py`。跑一次 240 题、事后按 qid 前缀拆 v1/v2，避免两次运行的环境漂移。

|---|---|---|---|---|---|---|
| 全部 240 | 220 | 0.586 | 0.432 | 0.602 | 20/20 | 5.02s |
| v1（100 题） | 92 | 0.522 | 0.377 | **0.587** | 8/8 | 4.80s |
| v2（新增 140 题） | 128 | 0.633 | 0.472 | 0.613 | 12/12 | 5.07s |

**第一件好事：v1 被精确复现。** E004 正确率 0.582、R@5 0.522、P95 4.81s；E005 的 v1 子集 0.587 / 0.522 / 4.80s。同一配置隔一小时复跑，指标漂移在 0.5pp 内——说明**评测结果是稳的，不是抽到好样本**。这一条比数字本身重要：没有它，前面所有对比都可能是噪音。

**第二件值得注意的事：v2 的多跳题「好检但不更好答」。**

| 题型 | v1 R@5 → 正确率 | v2 R@5 → 正确率 |
|---|---|---|
| 单跳 | 0.654 → 0.663 | 0.708 → 0.708 |
| **多跳** | **0.375 → 0.458** | **0.618 → 0.471** |
| 改写 | 0.312 → 0.531 | 0.409 → 0.523 |

v2 多跳题 R@5 比 v1 高 24pp（0.375→0.618），**正确率几乎没动**（0.458→0.471，+1.3pp）。两种解释都成立：① v2 多跳题多为「同页相邻小节」，召回容易但综合两处信息仍难；② 多跳题瓶颈已从「找得到」变成「拼得对」，生成侧才是天花板。

无论哪种，都指向同一结论：**继续堆检索手段（加召回、加深 rerank）对多跳题收益已经很小**，下一步该动的是提示词里的多跳推理结构（强制分步引用、先列各片段结论再合并），而不是再调检索参数。

**为什么简历仍用 v1 口径**：v2 多跳题偏易（多个出题 agent 自评时都提到「最弱的两题是同页相邻小节切开」），把 240 题的 0.586 单独拎出来会显得比 v1 好看，但那是题目构成变化，不是系统变强。**主口径 = v1（100 题）**，v2 作为「样本翻倍后结论不反转」的稳健性证据。
