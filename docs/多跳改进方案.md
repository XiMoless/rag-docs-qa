# 多跳题专项改进方案（E006 待跑）

来源：E005 暴露的事实——**v2 多跳题 R@5 比 v1 高 24pp（0.375→0.618），正确率只涨 1.3pp（0.458→0.471）**。检索已经找得到，答不对。所以下一次实验不动检索，只动生成侧。

## 要验证的假设

> H1：多跳题答错的主因是「模型只用了 top-5 里的第一个相关片段就下结论」，没有把两处信息拼起来。

若 H1 成立，强制「先分片段取结论、再合并」的提示词结构应让多跳正确率明显上升（≥5pp），且单跳题不下降（±2pp 内）。

## 三个可对比的 prompt 变体（都要跑满 240 题）

- **P0 现状**（baseline，已有 E005）：`SYSTEM_PROMPT` + 片段列表。
- **P1 分步引用**：要求模型先对每个片段写一句「该片段支持什么/不支持什么」，再给结论。代价：输出变长，P95 上涨。
- **P2 数字落点**：要求结论句后必须标 `[片段编号]`，且凡涉及具体参数/默认值必须原样抄写标识符（不允许改写英文术语）。

## 判定标准（先写死，跑完不打折）

| 指标 | 期望 |
|---|---|
| multi-hop judge_acc | P1 或 P2 比 P0 高 ≥ 5pp |
| single-hop judge_acc | 下降不超过 2pp（否则是在牺牲简单题换难题） |
| no-answer 拒答 | 保持 20/20（加结构不能让模型变得爱编） |
| P95 | 不超过 8s（否则 demo 体验崩） |

四条同时满足才算改进成立；只满足「多跳涨了」不算——很可能只是把简单题拖下水。

## 实现方式

`src/ask.py` 已有 `prompt_version` 概念（config 里 `generation.prompt_version: v1`）。新增 `v2_stepwise` / `v3_cite_exact` 两个 prompt，用 `--prompt-version` 选，RESULTS 行备注写清用的是哪个。

## 如果 P1/P2 都不涨

那说明问题不在提示词，而在**多跳题的检索组合**——两处信息各自都在 top-20 里但不在 top-5 里，需要的是「多查询检索」（把一个问题拆成 2 个子查询分别检索再去重合并），而不是更好的提示词。那是 E007 的事，别在同一轮里混着试。
