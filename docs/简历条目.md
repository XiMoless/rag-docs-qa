## 面试要准备的三个「为什么」（数字背后的判断）

1. **为什么召回只有 0.664，而早期版本只有 0.37**：语料是英文文档、提问是中文，BM25 词法通道基本失效（纯 BM25 R@5 0.185，E102）；把中文问题用 LLM 翻成英文关键词后同一个 BM25 立刻到 0.500（E008）——**不是 BM25 不适合中文语料，是它没拿到能匹配的语言**。RRF 等权融合反而比纯向量低 7.6pp（E103 vs E101），因为弱通道把对的挤下去。
2. **为什么邻接扩展第一次实现反而制造了 4 条硬回归**：第一次用交错排列，+3.8pp 看着不错，但有 4 条从 1.0 掉到 0.0——长邻居把锚点挤出了 6000 字符的上下文预算。改成「**锚点优先 + 邻居显式标注**」后 +7.0pp 且零硬回归（E006→E007）。→ 讲「总分会掩盖硬回归，必须看配对变化」。
3. **为什么无答案题要分两类**：第一类是「语料里根本没有」（20 道，全部 20/20 拒答）；第二类是「主题在、但追问的具体事实不在」（12 道）。后者才是真考验——上下文看起来很相关，模型最容易编一个默认值出来。这类题的靶子必须用全库词面检索 0 命中来证明。

## 两个自己发现的 bug（比顺利更值得讲）

- **E001 作废**：`SYSTEM_PROMPT` 只 format 了 `{context}`、漏传 `{question}`，模型普遍回答「你没有提出具体问题」，正确率 0.293。补传后同配置复跑 0.484（+19.1pp）。
- **E003 部分作废**：rerank 接在「已经按 k_context=5 截断」的候选上，候选池只有 5 个，R@5 抬不动、只抬了 MRR。改成先取 20 个候选再 rerank，正确率 0.522→0.582。
